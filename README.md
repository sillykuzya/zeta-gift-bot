# zeta-gift-bot

Telegram-бот для розыгрыша NFT-подарков. Порядок: «Начать» → кубик определяет подарок сразу → серия заданий (TikTok-комментарии → модерация → подписка на спонсоров) → связь с менеджером за уже определённым подарком → менеджер отмечает выдачу в боте.

## Структура

```
config.py               настройки (токен, БД, ID группы модерации, админы, менеджеры)
db.py                    вся работа с PostgreSQL
states.py                FSM-состояния админ-панели
keyboards.py             инлайн-клавиатуры
replies.py               все текстовые реплики бота (пользователям и модераторам)
logic.py                 бизнес-логика воронки, кубика и модерации
scheduler.py             таймеры (APScheduler)
handlers/user.py         /start, кнопки «Начать»/«Поехали», приём скриншотов, проверка подписок
handlers/moderation.py   кнопки Одобрить/Отклонить в чате модераторов
handlers/manager.py      уведомление менеджеру + кнопка «Выдано», /given, /waiting
handlers/admin.py        админ-панель /admin
main.py                  точка входа
```

## Как выглядит воронка

1. `/start` → приветствие + кнопка **«Начать»**.
2. Кубик 🎲 бросается сразу — бот определяет и показывает подарок, кнопка **«Поехали»**.
3. Шаг 1 — комментарий под чужим видео (5 мин) → скриншот → модерация.
4. Шаг 2 — комментарий под 10 видео (20 мин) → скриншоты → модерация.
5. Подписка на спонсоров → проверка.
6. Как только пользователь доходит до этого шага, менеджерам (`MANAGER_IDS`, а если пусто — `ADMIN_IDS`) сразу приходит уведомление с юзернеймом/ID, номером подарка и кнопкой **«✅ Выдано»** — искать ID вручную не нужно.
7. Менеджер выдаёт подарок (обсуждает оплату 50 Stars и т.д.) и жмёт **«✅ Выдано»**. Если уведомление потерялось — команды `/waiting` (список всех, кто ждёт, с такой же кнопкой у каждого) или `/given <ID или @username>` (можно и без аргумента — бот спросит).
8. Статус пользователя переключается в финальный `gift_given`, ему приходит подтверждение. Повторный `/start` — бот отвечает, что подарок уже получен.

## Установка

```bash
git clone https://github.com/sillykuzya/zeta-gift-bot.git
cd zeta-gift-bot
python -m venv venv
source venv/bin/activate
pip install -r requirements.txt
```

При каждом новом запуске сессии активируй venv заново:

```bash
cd zeta-gift-bot
source venv/bin/activate
python main.py
```

Выйти из venv: `deactivate`.

Если `pip install` падает на сборке `pydantic-core` из исходников (частый случай на Termux с новым Python) — собери проект в Ubuntu через `proot-distro` или используй Python 3.12/3.13, там для aiogram есть готовые wheel-пакеты.

## Переменные окружения

Скопируй `.env.example` в `.env` и заполни:

```bash
cp .env.example .env
```

```bash
BOT_TOKEN=123456789:AAExampleTokenReplaceMe
DB_DSN=postgresql://zeta_user:zeta_password@localhost:5432/zeta
MODERATION_GROUP_ID=-1001234567890
ADMIN_IDS=111111111,222222222
MANAGER_IDS=333333333
MANAGER_USERNAME=your_manager
```

`config.py` подхватывает `.env` автоматически через `python-dotenv`. Можно и без файла — просто экспортировать эти переменные в оболочке.

`MODERATION_GROUP_ID` — ID группового чата модераторов. Бот должен быть в этой группе с правами удаления сообщений. Модераторов добавляй через `/admin → Модераторы` (их ID, членство в группе для этого не обязательно — права проверяются по таблице `moderators`).

`MANAGER_IDS` — кто может писать `/given <user_id>` в личку боту. Может не совпадать с `ADMIN_IDS`, если менеджер — не тот же человек, что администратор.

Для каждого спонсорского канала `chat_ref` (в разделе Спонсоры) должен быть `@username` или числовой ID канала, и бот обязан быть администратором этого канала — иначе `get_chat_member` не сработает.

## Что не покрыто ТЗ и решено по умолчанию

- Ровно 10 скриншотов на шаге 2: бот принимает первые 10 присланных фото и автоматически отправляет их на модерацию по достижении десятого. Скриншоты, присланные одним альбомом, считаются молча — прогресс 1/10, 2/10 и т. д. бот показывает только при отправке по одному.
- На шаге 1 нужен ровно один скриншот — если прислать альбом из нескольких фото, бот целиком его отклоняет и просит одно фото, не засчитывая ни одно из них.
- Первый список текстов (шаг 1) сделан таким же редактируемым через `/admin → Тексты заданий`, как и второй — ТЗ требовало этого явно только для шага 2, но иметь единый интерфейс проще, чем хардкодить один список.
- Если спонсоров не добавлено, шаг 3 пропускается автоматически.
- Кубик и определение подарка перенесены в начало воронки (сразу после «Начать»), а не в конец — так пользователь видит, за что именно выполняет задания.
- Подтверждение выдачи подарка — как только пользователь доходит до этого шага, менеджерам сразу приходит карточка с кнопкой «Выдано» (плюс резервные `/waiting` и `/given <ID/@username>`), а не отдельная функция внутри переписки менеджера с пользователем вне бота — у бота нет к ней доступа.
- Поиск по `@username` работает только для тех, кто хотя бы раз писал боту (`/start`) — Telegram не даёт резолвить произвольный username в ID иначе. Для всех остальных (модераторы, баны, given) можно ввести и числовой ID.
